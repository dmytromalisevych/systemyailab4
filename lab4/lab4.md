## 1.1. Залізо
| Характеристика | Значення | Джерело |
| :--- | :--- | :--- |
| **Процесор і RAM** | Apple Silicon (MacBook Pro), Об'єднана пам'ять (Unified Memory) | Системна інформація macOS («Про цей комп'ютер») |
| **Відеокарта (VRAM)** | Інтегрований GPU Apple (використовує Unified Memory) | Системна інформація macOS |
| **Пропускна здатність** | ~100 ГБ/с | Офіційні специфікації базових чіпів M-серії від Apple |

## 1.2. Розрахунок
Завдяки архітектурі Unified Memory на macOS, система динамічно виділяє оперативну пам'ять під потреби відеоядра (VRAM). 
* **Пам'ять:** Моделі розміром 0.5B – 1.5B у квантизації Q4 потребують від 0.5 ГБ до 1.5 ГБ пам'яті (включно з базовим KV-кешем). Це ідеально вміщується в ОЗП мого MacBook без використання повільного файлу підкачки (swap).
* **Швидкість:** Враховуючи пропускну здатність пам'яті у 100 ГБ/с, для ваг обсягом ~400 МБ (0.5B модель) розрахункова стеля генерації сягає понад 150 tokens/s. Для ваг обсягом ~1 ГБ (1.5B модель) стеля становитиме близько 70–90 tokens/s.

## 1.3. Вибір моделі й рантайму
* **Рантайм:** Ollama. Обрано через те, що під капотом використовується `llama.cpp`, який має нативну оптимізацію під Metal API (Apple Silicon), що гарантує максимальну продуктивність на macOS.
* **Модель:** `qwen2.5:1.5b` (Q4 квантизація).
* **Обґрунтування:** Розмір в 1 ГБ не перевантажує систему, дозволяючи комп'ютеру працювати без затримок. Формат `Instruct` обрано для зручної роботи в режимі чат-асистента. Режим міркування (Reasoning) вимкнено, оскільки для базових діалогових задач він лише сповільнює роботу.

## 1.4. Вимірювання до оптимізації
Первинний запуск проводився на базовій мікро-моделі **`qwen:0.5b`**.
* Вимірювання (`bench.py --label before`) показали швидкість **170.5 tokens/s**.
* **Аналіз:** Швидкість навіть перевищила очікування, проте під час перевірки якості (10 промптів) виявилася критична проблема. Модель жахливо працює з кирилицею, має бідний словниковий запас українською мовою та видає сильні фактологічні галюцинації (приклад збережено у скріншоті в папці `demo`).

## 1.5. Оптимізація і вимірювання після
Для вирішення проблеми з якістю генерації та мовою, модель було змінено на більшу — **`qwen2.5:1.5b`**.
* Вимірювання (`bench.py --label after`) показали швидкість **69.3 tokens/s**.
* **Аналіз:** Як і прогнозувалося в п.1.2, через збільшення розміру ваг швидкість впала. Проте 69 tokens/s залишається блискавичним результатом для сприйняття користувачем. Якість відповідей українською мовою стала абсолютно адекватною, фактологічні помилки на базових питаннях зникли.

## 1.6. Власний застосунок
Розроблено локальний AI-Асистент у вигляді веб-чату.
* **Архітектура:** Клієнтська частина написана на чистому HTML/CSS та JavaScript (`index.html`, `app.js`). Застосунок робить прямі HTTP POST запити з JSON до OpenAI-сумісного API Ollama за адресою `http://localhost:11434/v1`.
* **Параметри генерації:**
  * `temperature: 0.3` — обрано низьке значення, щоб мінімізувати ймовірність галюцинацій та зробити відповіді мікро-моделі більш точними та прогнозованими.
  * `max_tokens: 150` — жорсткий ліміт для захисту від безкінечного зациклення або генерації "сміття", що іноді трапляється з моделями малого розміру.
* **UI/UX:** Інтерфейс підтримує стрімінг відповідей (посимвольний вивід), має обробку стану завантаження та виводить зрозуміле повідомлення у разі відсутності з'єднання з сервером. Інструкція із запуску додана у файл `readme.md`.

## 1.7. Перевірка та демонстрація
**Тестові сценарії:**
1. **Базове привітання.** 
   * *Промпт:* "Привіт, ти хто?"
   * *Результат:* Успіх. Модель коректно вітається українською.
2. **Перевірка мовного контексту.** 
   * *Промпт:* "Ти розумієш українську?"
   * *Результат:* Успіх. Модель підтверджує знання мови і не перемикається на англійську.
3. **Фактологія та крайовий випадок (Виправлення помилки).** 
   * *Промпт:* "Хто такий Зеленський?"
   * *Результат:* До оптимізації (`qwen:0.5b`) застосунок видавав маячню про "східноукраїнське філософство" (доказ у `demo/`). Після заміни моделі на `qwen2.5:1.5b` застосунок успішно впорався і видав коректну фактологічну довідку.
4. **Обробка серверних помилок (Крайовий випадок).** 
   * *Дія:* Вимкнено процес Ollama (`killall ollama`), відправлено будь-який промпт.
   * *Результат:* Успіх. Застосунок не зависає, ловить `ConnectionRefusedError` і виводить червоне повідомлення "Сервер недоступний. Перевірте, чи запущена Ollama".
5. **Тригер ліміту токенів.** 
   * *Промпт:* "Напиши детальне есе на 500 слів про історію України."
   * *Результат:* Успіх. Генерація коректно обривається на 150-му токені згідно з налаштуванням `max_tokens`, система не перевантажується.

## 1.8. Висновок
Локальне розгортання оптимізованих мікро-моделей (до 2B параметрів) через Ollama на платформі Apple Silicon дозволяє створювати автономні застосунки з нульовою затримкою мережі. Завдяки архітектурі Unified Memory швидкість генерації досягає 70-170 tokens/s. Головним інженерним викликом є пошук балансу між розміром моделі (для збереження здатності до розуміння контексту/мови) та лімітами пропускної здатності пам'яті. Модель `qwen2.5:1.5b` виявилася оптимальним рішенням для виконання цього завдання.
